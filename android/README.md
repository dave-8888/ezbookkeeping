# financially_free 安卓 App

原生 Kotlin / Jetpack Compose 应用，Android 8.0（API 26）及以上。通过内网连接本项目后端，使用 AI 工具调用完成自然语言记账、查账与资产更新。新对话由模型追问补充缺失信息；历史交易仍可使用原生表单补全。

## 服务端 AI 对话（0.6.0）

手机只发送文本、对话 ID 和消息 ID，后端完成模型调用、业务工具执行和上下文保存，手机展示服务返回的回复与结果。连接中断可点击“查看处理结果”，不会自动重复记账。模型整理回复失败时保留已经查询成功的数据。

需要同步升级后端并执行数据库迁移，再安装 APK。接口、上下文保存和恢复规则见 [服务端 AI 对话说明](docs/ai-tool-conversation.md)。

## 仅对话记账（0.4.0）

登录后直接进入原生对话记账。安卓端已移除账本网页容器、底部导航，以及明细、账户、统计、资产规划、人情往来等入口。网页端独立保留原有功能。

安卓端保留登录与双重验证、对话历史、自动记账、交易补全，以及必要设置（原生 AI 配置、登录记录、服务地址、重新连接、退出登录和清空本机聊天）。AI 设置支持 OpenAI、OpenAI 兼容服务、OpenRouter、Ollama 和 Google AI，沿用服务端现有配置与密钥；密钥留空时按服务端规则保留原值，更换兼容服务地址时需重新填写密钥。

APK 不再加载 `/mobile` 或依赖网页资源，安装时无需同步构建 `dist/`。返回键从设置或交易补全回到对话，在对话主页使用系统默认返回行为。保存结果不确定的消息保留「如何核实」说明，请另行在网页版核对，App 不自动重发。

覆盖安装保留现有加密会话和本机聊天数据库。

## 对话管理

主页右上角“＋”新增对话，左侧列表按钮查看、切换或删除对话；对话在首条消息后，由现有 AI 模型根据对话创建日期和首条内容生成标题（日期也计入总长度，最多 15 个字），生成成功后保持稳定。标题后台生成，不阻塞继续记账；失败时保留“日期＋记账”，重新打开对话或重新连接时重试。旧对话在打开时补生成 AI 标题。重启后恢复上次打开的对话，各服务器和账号分别保存。

删除整个对话前需要确认，仅删除该对话的本机聊天记录，已保存的账目不会删除。删除最后一个对话后自动创建空白对话。不支持单条消息删除。设置中的“清空本机聊天记录”仍清空当前账号所有对话的消息。

旧版聊天数据库升级后，原有消息按账号归入“历史对话”，保留已记账结果及待核实状态。AI 标题功能需要同步更新后端，新增接口为 `POST /api/v1/llm/conversations/generate_title.json`，复用个人或系统 AI 配置。旧服务不支持该接口时只显示日期标题。

## 安装和连接

1. 安装 `app/build/outputs/apk/debug/app-debug.apk`。这是用于手动安装的调试签名测试包，不是商店发布包。
2. 手机与服务端处于同一可互访网络，输入**服务根地址**，例如 `http://192.168.1.10:18888/`。反向代理子路径可填写 `https://host.example/finance/`；不要追加 `api/`。手机上的 `localhost` 指向手机自身。
3. 使用现有用户名或邮箱、密码登录。支持双重验证码或恢复码。账户、分类先在网页配置；个人 AI 模型可在 App 设置中配置。
4. 输入“午饭花了 30 元”或“今天工资到账 8000 元”。字段完整由服务执行保存；缺失字段时在对话中追问。旧消息仍可通过表单补全。

服务地址使用现有部署的实际端口。本仓库运行脚本的后端默认端口为 18888，Docker Compose 默认映射为 8080。服务器需监听手机可达的网卡；不需要开放公网端口。HTTPS 使用系统证书校验，内网 HTTP 通过显式网络配置支持。

首版仅做支出、收入，每条消息一笔。聊天展示缓存在手机，服务端另存对话上下文和执行结果，按账号隔离。清空聊天不会删除服务器交易。退出登录清除本机令牌，保留聊天记录。关闭系统备份和设备迁移，避免把聊天和会话复制到其他设备。

## 登录记录（0.2.0）

成功登录后，自动保存服务地址和用户名/邮箱。相同地址与用户名只保留一条，最近使用的记录优先显示；失败登录或未完成双重验证不保存。

登录页点击“切换账号”，可以自动填入地址和用户名，也可以修改或删除记录；已登录时，可从“设置 → 管理登录记录”管理。修改或删除只作用于本机登录记录，不改变当前会话、服务器账号或聊天数据。切换登录记录会清空已输入的密码，密码不保存。

从 0.1.0 覆盖安装时，会把上次成功登录的地址和用户名迁移为一条记录，无需重新输入。历史记录独立存储，无需更改聊天数据库。

## 构建

需要 JDK 17、Android SDK Platform 35 和 Build Tools 35.0.0。

```sh
cd android
# 在 local.properties 中填写 sdk.dir=/你的/Android/sdk
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest :app:lintDebug
# 已连接安卓设备或模拟器时：
./gradlew :app:connectedDebugAndroidTest
```

Gradle Wrapper 固定为 8.13，依赖版本在 Gradle 构建文件中固定。首次构建需要下载依赖。Android Studio 可以直接打开此目录。

本次构建环境 SDK 位于 `/Users/dave/Library/Android/sdk`。`local.properties` 与所有构建输出均被忽略，不需要提交。发布版本需要另行配置稳定签名，不应把私钥放入仓库。

## 实现与接口

- `Api` 处理服务地址、Bearer 令牌、中文语言、时区请求头、统一响应和目录数据加载。禁用自动网络重试及重定向。
- `TransactionRules` 移植现有添加交易默认值与缺失字段逻辑。交易类型收入为 2、支出为 3；分类类型收入为 1、支出为 2。金额使用整数分，表单使用十进制定点转换。
- `ChatViewModel` 管理认证、刷新、识别、保存和表单流程；`Storage` 使用 Room 保存聊天和提交状态，Android Keystore 加密保护令牌。密码与模型密钥不落盘。
- 网页功能保留；后端新增对话编排接口与持久化表。

调用现有接口：`authorize.json`、`2fa/authorize.json`、`2fa/recovery.json`、`v1/tokens/refresh.json`、账户/分类/标签列表、`v1/users/settings/llm/get.json`、`v1/llm/transactions/recognize_transaction_text.json`、`v1/transactions/add.json`；路径统一相对于服务根地址下的 `api/`。

交易保存前，先持久化 `saving` 状态和固定 `clientSessionId`。成功后保存交易 ID。进程重启时，`saving` 恢复为“结果待核实”，`recognizing` 恢复为失败；不会自动重发。保存响应丢失、HTTP 5xx 等无法确认结果的情况引导到网页核实。请保持后端 `[duplicate_checker] duplicate_submissions_interval` 大于 0；当前项目配置为 300 秒。该机制不是无限期幂等保证，因此不提供对未知结果的直接重试按钮。

## AI 工具对话（0.5.0）

输入首先交给当前配置的 AI 模型。模型结合当前对话选择工具，App 校验参数、调用已登录账号的真实接口，再把执行结果交回模型。模型可以继续调用工具、追问或组织自然语言回答；发送流程已移除关键词分流，不再要求固定句式。

例如“帮我看看资产，第一项应该是六千”“昨天工资到账多少”“这笔午饭花了三十，记一下”，由模型决定查询、补充信息或记账操作。

已注册工具：账户及资产查询、日期范围收支查询、可记账账户/分类/标签查询、设置账户余额、创建收入/支出。当前工具调用项目 API，未连接外部 MCP 服务。

- 复用个人或系统 AI 配置，支持 OpenAI、OpenAI 兼容服务、OpenRouter、Ollama 和 Google AI 的原生工具协议；所选模型本身必须支持工具调用。不支持或旧后端缺少新接口时明确提示，不退回固定关键词回复。
- 查询返回真实数据和币种，模型负责理解及回答。资产默认不含隐藏，显式范围在当前对话继承。账户编号/ID/余额快照和工具结果随聊天记录持久化，按服务器、账号、对话隔离。
- 收支查询按手机当前时区的自然日范围执行，含首尾日期，最多跨366天；超过5000笔要求缩小范围。合计包含全部分页，明细每次返回50笔，模型可继续翻页。各币种分别汇总，隐藏账户交易默认包含。
- 模型可以先查询再修改。余额设置使用现有余额校准，不产生收入/支出流水；修改前核对目标及原余额，后端用 expectedBalance 防止覆盖并发变化，写后再次回读。记账也校验目录ID、币种和金额，并回读交易。
- 每条用户消息最多8轮模型调用、每轮最多4个工具调用，最多一次写入尝试；多笔写入由模型引导分次操作。写入前持久化待核实状态，成功后保存核实凭据；结果未知停止执行，不自动重发。最终模型回答失败也保留已完成写入的凭据。
- 旧对话和旧的交易补全表单仍可使用。新对话的信息缺失通过模型追问补充，聊天里的固定核实凭据与模型回答分开展示。

**需同步更新后端和 APK**：新增 `POST /api/v1/llm/conversations/chat.json`，模型密钥保留在服务端。后端每次只执行模型推理；App 在受控工具执行器中调用原有业务接口，并将结果送回继续推理。旧后端不具备该接口，无法运行新版对话流程。

实现与验证见 [AI 工具对话说明](docs/ai-tool-conversation.md)。
