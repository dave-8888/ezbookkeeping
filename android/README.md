# financially_free 安卓 App

原生 Kotlin / Jetpack Compose 应用，Android 8.0（API 26）及以上。通过内网连接本项目后端，支持单笔支出、收入的文字识别和自动记账。信息不足时使用原生表单补全。

## 账本与对话记账整合（0.3.0）

登录后默认打开账本；点击底部中间「＋」，选择「对话记账」进入原生对话页面，选择「新增交易」手动记账。对话页左上角或系统返回键回到账本，顶部不再显示分段切换入口。对话记账保留原生实现；账本复用服务端已有的手机端网页，包含明细、账户、统计、资产规划和设置等入口。AI 设置与保存结果核实也在 App 内打开。网页保留自己的底部菜单，App 不再叠加一排底部导航。

安装新版 APK 时，需要同时部署本次构建的网页资源（`npm run build` 生成的 `dist/`）。服务根地址下的 `/mobile` 必须可访问，反向代理子路径同样支持。旧网页或过旧的 Android System WebView 会显示提示与重试入口，不会悄悄要求第二次登录。此版本没有改变后端 API 或数据库结构。

原生登录后，账本通过限定来源、限定主文档的消息接口获取会话。网页的令牌只放在内存中，持久化仍由 Android Keystore 加密存储；刷新令牌和退出登录同步到原生。切换期间保留网页表单，原生成功记账后刷新账单、账户、统计和首页，其他编辑页面保留输入。返回对话时重新加载账户和分类。系统返回键先关闭网页弹层、返回上一级页面，在网页首页则将 App 放到后台。

外观统一跟随 Android 系统；内嵌模式隐藏浏览器专用的 PIN / WebAuthn 应用锁入口，因为它不能保护原生聊天。普通浏览器中的主题和应用锁功能保持原有行为。文件选择使用系统选择器；Blob 文件导出使用系统「保存到」界面，单文件上限 20 MB，超出时需在浏览器导出。切换账号或服务子路径时清理网页的本地偏好和缓存草稿；退出登录清理网页存储。网页未保存表单在当前会话的入口切换中保留，进程结束或页面重新加载仍遵循原网页自身的草稿恢复能力。

验证与截图见 [整合验证记录](docs/hybrid-verification.md)、[日间界面](docs/hybrid-day.png)、[夜间界面](docs/hybrid-night.png) 和 [原生记账](docs/hybrid-chat.png)。

## 安装和连接

1. 安装 `app/build/outputs/apk/debug/app-debug.apk`。这是用于手动安装的调试签名测试包，不是商店发布包。
2. 手机与服务端处于同一可互访网络，输入**服务根地址**，例如 `http://192.168.1.10:18888/`。反向代理子路径可填写 `https://host.example/finance/`；不要追加 `api/`。手机上的 `localhost` 指向手机自身。
3. 使用现有用户名或邮箱、密码登录。支持双重验证码或恢复码。账户、分类和个人 AI 模型先在原有网页配置。
4. 输入“午饭花了 30 元”或“今天工资到账 8000 元”。字段完整会直接保存；缺失字段时点击“补全交易”。

服务地址使用现有部署的实际端口。本仓库运行脚本的后端默认端口为 18888，Docker Compose 默认映射为 8080。服务器需监听手机可达的网卡；不需要开放公网端口。HTTPS 使用系统证书校验，内网 HTTP 通过显式网络配置支持。

首版仅做支出、收入，每条消息一笔。聊天记录在手机本机保存，按完整服务器根地址与账号隔离。清空聊天不会删除服务器交易。退出登录清除本机令牌，保留聊天记录。关闭系统备份和设备迁移，避免把聊天和会话复制到其他设备。

## 登录记录（0.2.0）

成功登录后，自动保存服务地址和用户名/邮箱。相同地址与用户名只保留一条，最近使用的记录优先显示；失败登录或未完成双重验证不保存。

登录页点击“切换账号”，可以自动填入地址和用户名，也可以修改或删除记录；已登录时，可从“设置 → 管理登录记录”管理。修改或删除只作用于本机登录记录，不改变当前会话、服务器账号或聊天数据。切换登录记录会清空已输入的密码，密码不保存。

从 0.1.0 覆盖安装时，会把上次成功登录的地址和用户名迁移为一条记录，无需重新输入。历史记录独立存储，无需更改聊天数据库。

## 构建

需要 JDK 17、Android SDK Platform 35 和 Build Tools 35.0.0。

```sh
cd android
# 在 local.properties 中填写 sdk.dir=/你的/Android/sdk
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest :app:lintDebug
# 已连接安卓设备或模拟器时：
./gradlew :app:connectedDebugAndroidTest
```

Gradle Wrapper 固定为 8.13，依赖版本在 Gradle 构建文件中固定。首次构建需要下载依赖。Android Studio 可以直接打开此目录。

本次构建环境 SDK 位于 `/Users/dave/Library/Android/sdk`。`local.properties` 与所有构建输出均被忽略，不需要提交。发布版本需要另行配置稳定签名，不应把私钥放入仓库。

## 实现与接口

- `Api` 处理服务地址、Bearer 令牌、中文语言、时区请求头、统一响应和目录数据加载。禁用自动网络重试及重定向。
- `TransactionRules` 移植现有添加交易默认值与缺失字段逻辑。交易类型收入为 2、支出为 3；分类类型收入为 1、支出为 2。金额使用整数分，表单使用十进制定点转换。
- `ChatViewModel` 管理认证、刷新、识别、保存和表单流程；`Storage` 使用 Room 保存聊天和提交状态，Android Keystore 加密保护令牌。密码与模型密钥不落盘。
- 原有网页和后端接口、数据库结构没有修改。

调用现有接口：`authorize.json`、`2fa/authorize.json`、`2fa/recovery.json`、`v1/tokens/refresh.json`、账户/分类/标签列表、`v1/users/settings/llm/get.json`、`v1/llm/transactions/recognize_transaction_text.json`、`v1/transactions/add.json`；路径统一相对于服务根地址下的 `api/`。

交易保存前，先持久化 `saving` 状态和固定 `clientSessionId`。成功后保存交易 ID。进程重启时，`saving` 恢复为“结果待核实”，`recognizing` 恢复为失败；不会自动重发。保存响应丢失、HTTP 5xx 等无法确认结果的情况引导到网页核实。请保持后端 `[duplicate_checker] duplicate_submissions_interval` 大于 0；当前项目配置为 300 秒。该机制不是无限期幂等保证，因此不提供对未知结果的直接重试按钮。

## 验证范围

单元测试覆盖支出/收入、金额精度、默认账户、分类推断及不匹配、缺失字段、转账拒绝、序列化与提交 ID、服务子路径、认证头、错误和禁止重定向/重试。

安卓设备测试使用设备内的 MockWebServer，覆盖密码登录和双重验证、自动入账、表单补全、Activity 重建，以及 Room 的账号隔离和中断恢复。测试会写入专用模拟器本机数据，不连接个人账本。

另在独立临时 SQLite 数据库的现有 Go 后端实例上验证了收入、支出创建及回读，核对金额、账户、分类与重复提交 ID。还通过模拟器连接该隔离后端，完成文字识别（使用本地模拟模型）、自动入账与强制停止后的历史恢复，确认未重复提交。外部 AI 厂商与用户实际手机/内网仍需按实际部署验收。

## 日夜外观

界面跟随 Android 系统深色模式自动切换。深浅色模式共用布局，使用浅灰/深色底色与简洁收据卡片，点击卡片可展开详情。登录、交易补全、设置和登录记录使用统一主题，状态栏和启动背景同步适配。截图见 `docs/ui-day.png` 和 `docs/ui-night.png`，验证记录见 `docs/design-qa.md`。


## UI 简化

对话主页合并重复标题，账单按天分组，输入区统一使用发送图标。补全交易优先呈现缺失信息，已有信息可修改，备注和标签放在“更多信息”中。设置采用分组页面，老用户登录默认收起服务配置。10 项修改和最新截图见 [UI 简化验证](docs/ui-simplification/README.md)。
