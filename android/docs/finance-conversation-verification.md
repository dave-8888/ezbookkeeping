# 对话查账与资产更新验证

> 本文记录0.4版规则分流阶段。当前0.5版已替换为AI原生工具调用，最新说明见 [AI工具对话](ai-tool-conversation.md)。

日期：2026-09-13。实现范围为截图中确认的 6 项需求，不连接或修改用户真实账本。

## 实现结果

- 输入先区分查询、资产列表、余额更新，再进入原有 AI 交易识别。截图原话及常见同义表达均可用。
- 今日收支遍历服务端游标分页，按手机当前时区的自然日筛选，包含隐藏账户交易；按原始有符号金额分币种求和，不计算转账或余额校准。
- 资产是当前资金账户余额。默认不含隐藏，显式范围在同一对话继承；隐藏父账户的子账户继承隐藏状态，仅统计叶子账户。资产、负债和净资产分币种展示，不混合货币。
- 明细可展开；收入和资产列表默认展开。序号对应展示时的账户 ID 与余额，并持久化到当前账号、服务器、对话的聊天数据，重启后仍可引用。
- 更新是设为目标余额，复用既有余额校准，不生成流水。更新前检查对象、币种及余额；后端新增可选 expectedBalance 并在 SQL 更新条件中比对，避免覆盖并发余额变化。成功后回读并发布最新完整列表。
- 进程中断或响应不确定时，保存“更新结果待核实”，不自动重复写入；必须重新查询建立列表上下文。切换对话不能借用其他对话序号。

## 验证

- Android JVM 单元测试：30 项通过，其中新增 6 项覆盖原话解析与记账区分、隐藏父子账户、负债及多币种、序号绑定、绝对余额写入、过期及币种错误拒绝、分页与夏令时边界、空数据与异常游标。
- Android 模拟器（ezb_mvp_test，Android 15）：8 项通过，包含六条请求完整流程、ViewModel 重建后的上下文恢复、切换对话拒绝旧序号、原有记账回归、中断状态恢复、存储隔离及迁移，以及明细展开/收起。
- Go 定向测试：`go test ./pkg/services ./pkg/api -run 'TestConversationBalance|TestAccountBalanceModifyRequest' -count=1` 通过。覆盖余额比较更新、过期拒绝、账号隔离、零余额、负余额、旧调用兼容与不生成交易。
- Debug APK 构建、Android lint 通过。查询卡片截图已人工核对文字、明细与展开控制，无裁切，见 [查询卡片截图](finance-query.png)。截图为组件测试的模拟数据。

## 使用边界与交付

- APK：`android/app/build/outputs/apk/debug/app-debug.apk`，调试签名安装包。
- 后端需同步更新后使用新版 APK；旧后端会忽略 expectedBalance，无法提供本次新增的并发保护。本轮未部署后端、未安装到用户真实手机。
- 该次仅支持已确认的今日收支、当前资产及序号设定余额。不是任意范围的通用 AI 查账；命名账户过滤、昨日/月度查询、增减金额和批量修改不在本次范围。
- 多币种不折算；资产汇总不读取网页本机的“排除账户”偏好。时区和隐藏范围均在结果中标注。
- 所有验证使用模拟服务或临时数据库；实际手机与部署环境尚需安装后验证连接。
