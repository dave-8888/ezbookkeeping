# 资产规划交付说明

本文档对应 `WS-30` 首期资产规划能力，供使用、接口联调、部署验收和回滚使用。

## 功能范围

- 每位用户仅维护一个净资产计划。
- 创建计划时，以创建日的实际净资产、默认币种和账户排除范围作为冻结起点。
- 计划按用户所在自然日，从起点金额直线增长到目标金额；目标日期必须晚于当天，目标金额必须高于冻结起点。
- 修改计划只更新目标金额和目标日期，仍从原冻结起点重算；删除后可以重新创建。
- 净资产视图显示实际线和计划线；总资产、总负债视图只显示实际线。
- 页面显示目标、起点、当前净资产、今日计划值、差额、完成比例、领先/落后/持平和到期结果。
- 首期不包含多目标、阶段目标、提醒、自动预测、未来收支推演或首页卡片。

桌面端从侧栏进入“资产规划”；移动端从设置页进入“资产规划”。创建计划时采用当前资产统计的默认账户筛选，之后修改目标不会改变已冻结的币种或账户范围。

## 计算与数据口径

计划日金额按下式计算：

```text
起点金额 +（目标金额 - 起点金额）× 已过自然日数 ÷ 总自然日数
```

中间值使用精确整数运算，非整除结果向零截断，目标日严格等于目标金额。金额使用系统既有的整数最小货币单位，不使用浮点数。

实际净资产沿用现有资产趋势口径：账户余额按符号汇总，以计划创建时冻结的默认币种折算，并使用创建时冻结的账户排除范围。无法换算的账户沿用现有趋势逻辑而跳过。到期历史净资产仍按最新汇率重算，因此后续汇率变化可能改变到期日折算结果；首期未引入汇率快照或到期结算。

## API 契约

以下接口位于现有 JWT 鉴权组 `/api/v1`。客户端还应按现有约定发送 `X-Timezone-Name`（IANA 时区名）或 `X-Timezone-Offset`（分钟），服务端以此判定自然日。

| 方法 | 路径 | 请求体 | 成功结果 |
| --- | --- | --- | --- |
| `GET` | `/api/v1/asset_plans/get.json` | 无 | 当前计划；无计划时 `result` 为 `null` |
| `POST` | `/api/v1/asset_plans/add.json` | `targetAmount`、`targetDate`、可选 `excludedAccountIds` | 新计划 |
| `POST` | `/api/v1/asset_plans/modify.json` | `targetAmount`、`targetDate` | 修改后的计划 |
| `POST` | `/api/v1/asset_plans/delete.json` | 无 | `true` |

请求示例：

```json
{
  "targetAmount": 100000000,
  "targetDate": "2027-12-31",
  "excludedAccountIds": ["123", "456"]
}
```

`targetDate` 必须使用 `YYYY-MM-DD`。`targetAmount` 是整数最小货币单位；`excludedAccountIds` 必须属于当前用户，服务端会去重并解析为叶子账户范围。重复创建、计划不存在、非法目标日期、目标金额不高于起点或越权账户范围均返回现有统一错误响应。

计划响应的 `result` 字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `targetAmount` | integer | 目标金额 |
| `targetDate` | string | 目标日期，`YYYY-MM-DD` |
| `startAmount` | integer | 创建日冻结净资产 |
| `startDate` | string | 冻结起点日期 |
| `currency` | string | 创建时冻结的默认币种 |
| `excludedAccountIds` | string[] | 创建时冻结的排除账户 |
| `currentActualNetWorth` | integer | 当前实际净资产 |
| `todayPlannedNetWorth` | integer | 今日计划值 |
| `differenceAmount` | integer | 当前实际值减今日计划值 |
| `completionPercentage` | string | 精确完成比例的十进制字符串 |
| `status` | string | `in_progress`、`achieved` 或 `not_achieved` |
| `comparisonStatus` | string | `ahead`、`behind` 或 `on_track` |
| `targetDateActualNetWorth` | integer | 到期后返回的目标日实际净资产 |

## 数据库迁移

本次升级只新增 `asset_plan` 表，不修改既有表。`uid` 是主键，同时保证单用户单计划；表中保存目标、冻结起点、币种、排除账户和创建/更新时间。

项目使用 XORM `Sync2` 正向同步，没有 down migration。默认配置 `conf/financially_free.ini` 中 `database.auto_update_database = true`，服务启动时会创建或同步新表。若生产环境关闭了自动同步，应在启动新版本前显式执行：

```sh
./financially_free --conf-path /实际路径/financially_free.ini database update
```

该命令必须使用与应用实例相同的配置。SQLite、MySQL 和 PostgreSQL 均走同一应用命令；不要在未备份时手写生产 DDL。

## 部署清单

1. 记录待部署提交和当前应用版本，确认前后端来自同一构建产物。
2. 备份数据库；同时按既有运维流程备份配置、上传文件和密钥保管位置。不要把真实配置或凭证写入工单、日志或提交。
3. 在非生产环境执行 `./financially_free --conf-path /实际路径/financially_free.ini database update`；确认日志包含 `asset plan table maintained successfully`。
4. 停止旧应用，部署新二进制及同批次 `public` 前端资源，再启动应用。若启用了自动数据库同步，第 3 步可以作为预演，启动时仍会安全地重复同步。
5. 检查 `/healthz.json`，使用测试账号登录，在桌面端和移动端各完成一次页面加载。
6. 创建未来日期、金额高于当前净资产的计划；刷新确认数据持久化，检查净资产计划线以及总资产/总负债仅实际线。
7. 修改目标后确认起点不变；删除后确认回到空状态且可重新创建。
8. 检查明暗主题、窄屏布局、退出后换账号的数据隔离，以及应用日志中是否出现迁移或资产规划错误。

仓库级发布前验证命令：

```sh
go test ./pkg/models ./pkg/services ./pkg/api ./cmd
go test -race ./pkg/models ./pkg/services ./pkg/api ./cmd
go vet ./...
go test -run '^$' ./...
npx vue-tsc --noEmit
npm run lint
npm test -- --runInBand
npm run build
git diff --check
```

完整 `go test ./...` 还会访问在线汇率源，并包含依赖当前进程标识的 Unix socket 测试。发布判断应区分环境依赖失败与本次资产规划相关包失败，不得把未通过的全仓测试写成通过。

## 回滚清单

首选回滚方式是不删除数据表：

1. 停止新版本应用。
2. 恢复上一版二进制和与其配套的 `public` 前端资源。
3. 保留 `asset_plan` 表；旧版本不会访问该新增表，计划数据可供再次升级后继续使用。
4. 启动旧版本并检查 `/healthz.json`、登录、账户统计和资产趋势。
5. 若迁移或部署已影响其他表，停止操作并从升级前数据库备份整体恢复。

只有在确认不再需要计划数据并已完成数据库备份后，数据库管理员才可人工删除 `asset_plan` 表。删除会永久丢失所有用户的计划，且不属于应用内置回滚流程，不应作为常规回滚步骤。

- 新增单一净资产目标的创建、查询、修改、删除、计划线和进度状态。
- 新增 JWT 鉴权后的资产规划 API 与 `asset_plan` 持久化表。
- 资产规划缓存已纳入锁定、退出、强制退出和清空用户数据流程，避免跨账号残留。

- 兼容性注意：需要前后端同步部署；旧服务可忽略新增表，但旧前端无法使用新增接口。
