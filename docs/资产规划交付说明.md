# 月度资产规划

资产规划按月预演新增存款，并与账本净资产增加额比较。桌面与移动端共用月度编辑、预览和对比组件。

## 使用与计算

- 每位用户维护一个计划，自选开始和结束月份，包含首尾月份，最多 120 个月。
- 阶段按顺序连续执行：每月金额 × 重复月数。各阶段月数之和必须等于时间段长度。允许零存款月份，总计划金额必须大于零。
- 保存前可预览累计计划曲线。修改时间段和阶段后重新计算整个计划。
- 累计计划 = 从开始月份起各月计划金额之和，不按天线性插值。
- 基准 = 开始月份前一天的净资产。已有资产不计入新增存款。
- 每月实际 = 本月末净资产 − 上月末净资产；首月使用基准。当月截至今天。
- 累计实际 = 对应月末净资产 − 基准。实际值允许为负数。
- 月度差额 = 当月实际 − 当月计划；累计差额 = 累计实际 − 累计计划。
- 当月比较对象是完整月度计划，页面明确标识尚未结束的当月。未来月份实际值为空，曲线不延伸到未来。
- 计划结束后实际值截止结束月份末，不计入后续月份。
- 未来开始的计划在开始前不读取未来账本余额，也不预测基准。

实际值使用创建计划时确定的币种及账户排除范围；从旧计划转换时保留这两项。计算沿用带符号的资产、负债余额及最新汇率。投资盈亏、余额调整、历史记账修正和汇率变化会影响实际存款及历史基准；未引入汇率快照。无法换算的账户沿用既有资产趋势规则跳过。

## API

继续使用已鉴权的 `/api/v1/asset_plans/get.json`、`add.json`、`modify.json`、`delete.json`。客户端时区通过原有请求头传入。

创建/修改月度计划请求：

```json
{
  "startMonth": "2026-07",
  "endMonth": "2027-06",
  "stages": [
    { "amount": 500000, "repeat": 6 },
    { "amount": 800000, "repeat": 6 }
  ]
}
```

金额单位为分，例子表示前六个月每月 5,000 元、后六个月每月 8,000 元，累计 78,000 元。创建时可附 `excludedAccountIds`，修改时保留已有范围。金额和累计值限制在 JavaScript 精确整数范围内。

响应新增 `monthly` 对象：

- `startMonth`、`endMonth`、`stages`：保存的预演设置。
- `baselineDate`、`baselineAmount`：基准日期、金额；未来计划基准金额为空。
- `asOfDate`：服务端按用户时区判定的今天。
- `totalPlanned`：整个计划累计金额。
- `months`：逐月返回 `month`、`planned`、`cumulativePlanned`、`actual`、`cumulativeActual`、`difference` 和 `actualThrough`。

`difference` 是累计差额；未来月的实际及差额字段为空。月度界面只使用 `monthly` 内的计算结果，外层旧目标字段不代表月度净资产目标。

## 兼容与迁移

- `asset_plan` 表新增可空 TEXT 列 `monthly_schedule`，通过现有 XORM Sync2 迁移。
- 旧计划未保存新方案前保持原数据；新界面展示旧目标和转换入口，不擅自推断每月金额。
- 保存新方案后写入阶段 JSON，更新起止日期和计划总额；保持用户、币种和账户范围不变。
- 旧线性计划接口保留兼容读取和原有校验。月度计划禁止通过旧格式修改，避免误覆盖。
- 前后端需要同步升级，运行中的旧后端需重新构建并重启。`database.auto_update_database` 关闭时，按项目原有 `database update` 流程更新表。
- 降级旧版本前备份计划表；旧版本不能正确解释已经转换的月度计划。

## 验证

- Go 模型测试覆盖连续阶段、跨年、零存款月份、时间段和月数校验、金额上限。
- API 测试覆盖历史基准、负增长、闰年月末、当月部分实际、未来计划、到期截止、旧计划转换和无效输入不覆盖原计划。
- SQLite 服务测试覆盖阶段持久化、修改开始月份、账户范围保留及用户隔离。
- 前端测试覆盖阶段预演、日期跨度、分金额解析和累计金额上限。
- 页面使用独立模拟数据检查桌面深色、手机浅色、金额编辑、月数校验和保存反馈，不更改真实账本。

## 目标与消费规划（version 2）

新编辑器将计划升级为 `version: 2`，仍存储在 `monthly_schedule` JSON 中，无新增表或字段。原月度计划在用户保存前保持原格式；编辑时把顺序阶段换成各自的开始日期，默认月末存入，保留原月度分布。

- `finalGoal`：结束月份月末的总净资产目标，包含已有资产；金额大于零。外层 `targetAmount` 在 v2 中也表示此目标。
- `goals`：短期目标（稳定 ID、名称、金额、目标日期），仅作为用途和里程碑，不重复增加预测金额。
- `stages`：可并行的存款安排，包含名称、金额、开始日期、每月存款日、可选关联目标。`repeat` 表示存入次数；或用 `endDate` 加 `repeat: 0` 指定截止日期（含当天）。不存在的存款日按月末处理。首次存入日期不得早于开始日期，所有次数须落在整体期间内。
- `expenses`：预期消费的名称、金额、日期及可选目标关联。到期仅扣减预测，不生成真实交易。目标达成本身不扣钱。
- 各月 `income`、`expense` 分别为计划存入及预期消费；`planned` / `cumulativePlanned` 为净增加及累计净增加，可为负数。目标和消费金额、存款金额及累计收入/支出均限制在 JS 安全整数范围内，金额单位为分。
- 实际值仍调用原净资产计算服务，使用原币种和账户范围；计划变更不会写入账本或改变实际值。历史记账修正、投资盈亏、最新汇率的影响沿用原规则。
- v2 图表以 `projectionBase + cumulativePlanned` 展示预计净资产，以真实期初余额加实际累计增长展示实际净资产，另显示最终目标线及消费标记。未来计划暂以查询当日的净资产作为 `projectionBase`，页面明确提示为暂定起点；`baselineAmount` 和未来实际值仍为空。
- GET 可附 `detail_month=YYYY-MM`，返回所选月份的 `days` 明细。每日实际读取当天账本净资产，只返回截至今天的实际点，未来日期不延伸。每次最多读取一个月的每日明细，避免一次加载十年逐日数据。
- 短期目标展示截至目标日、关联存款安排的计划筹资总额及缺口，不推断真实账本资金属于哪个目标；删除目标时编辑器解除其存款、消费关联。

示例：10–12 月，每月长期存入 10,000 元，手机目标另存 4,000 元；12 月计划消费 12,000 元。三个月累计净增加依次为 14,000、28,000、30,000 元。最终预计资产为期初资产加 30,000 元。

验证覆盖并行存款与消费、目标金额不重复计入、闰年月末、周期越界、无效目标关联、金额溢出、消费已有资产、保存与读取、无效修改不覆盖原计划、规划变更不改变实际数据、每日与月度实际一致及未来实际为空。界面用隔离模拟数据验证桌面与 390px 窄屏、日期模式切换、保存及无效金额阻止提交，未写入用户账本。
